# VeilReceipt 操作指南

VeilReceipt 用零知识证明验收私密数据，再根据验收结果付款或退款。本指南适用于演示者、评委和首次接手项目的同学，覆盖启动、现场演示、异常案例、凭证复验与恢复。

版本：0.1.0，按 2026 年 10 月 7 日代码编写。每个操作都有 O01 至 O20 的编号，在 [操作背后的技术](OPERATIONS_TECHNICAL.zh-CN.md) 中使用相同编号。

当前演示使用合成数据、本地 EVM 和无价值的测试 ETH，不需要连接个人钱包、购买 ETH 或申请测试网代币。默认每笔订单托管 0.002 测试 ETH。

## 先完成一次三分钟演示

启动成功后，按下面的顺序走一遍即可展示核心价值。首次运行所需时间受电脑性能影响，现场以页面确认结果为准。

| 顺序 | 做什么 | 观众应看到什么 | 可以怎样讲 |
| --- | --- | --- | --- |
| 1 | 打开“现场演示”，选择“合格交付”，点击“运行真实验收” | 已付款；证明有效；验收合格 | 内容没有公开，合约仍能按约验收并付款。 |
| 2 | 切到“不合格就退款”，确认情境为“过期交付”，再次运行 | 已退款；证明有效；验收不合格 | 证明有效，说明计算符合约定；计算出的结果可以是不合格。 |
| 3 | 点击“带走并核验”，核验原始凭证 | 凭证有效，八组检查通过 | 把证据交给核验器，重新检查签名、证明和结算。 |
| 4 | 点击“修改结果，再核验一次” | 凭证被拒绝 | 只改公开结论，无法改写已经成立的证据。 |
| 5 | 点击“下载当前原始凭证” | 下载一份 JSON 文件 | 凭证可以离开这个页面，交给另一工具继续检查。 |

需要铺垫问题时，先展示“项目介绍”的第 2、3、4 章，再进入以上步骤。介绍页第 6、7 章的“运行付款演示”“运行退款演示”只负责打开对应场景；进入后仍需点击“运行真实验收”。

## O01 准备并启动项目

### 第一次安装

准备 Node.js 22.12 或以上版本，推荐 Node 24；还需要 npm、Git 和 tar。支持 macOS 或 Linux；Windows 使用 WSL。

在终端依次执行：

```sh
git clone https://github.com/uniqueskybaby/veilreceipt.git
cd veilreceipt
npm ci
npm run bootstrap
npm test
npm run test:model
npm run build
npm start
```

首次 bootstrap 需要联网下载固定版本的 Noir 工具和公开证明参数。看到服务输出 `VeilReceipt ready at http://127.0.0.1:4318` 后，在浏览器打开 [本地网站](http://127.0.0.1:4318/)。保留这个终端窗口。

成功标志是页面右上角显示“本地演示”，运行按钮可用。出现等待状态时，让服务完成初始化。

### 已经安装过

在项目根目录运行 `npm start` 即可。macOS 也可双击项目中的 `启动演示.command`；它适用于已经安装依赖并完成 bootstrap 的环境。

前端代码修改后，先执行 `npm run build`，再刷新页面；服务代码修改后，还需要重启服务。不要同时启动两个使用同一 `.runtime` 目录的服务。

结束演示时，先等待当前验收完成，再在运行服务的终端按 `Ctrl+C`。

桌面端用左侧章节导航，手机端用章节下拉框；底部按钮可以连续翻页。键盘焦点在章节正文区域时可用左右方向键翻页；焦点位于按钮、链接、下拉框或技术标签时，先使用这些控件自身的键盘操作。

放大图解后可横向滚动，按 `Esc` 或右上角关闭按钮退出。章节号码保存在网址中，可以复制具体章节的网址分享给同一台电脑上的演示者。

**介绍页的订单 A、订单 B 和第 8 章的“原理演示”是教学样例。** 实际订单号、交易和真实密码学核验要进入“现场演示”查看。

## O03 运行合格交付并付款

1. 点击“现场演示”，选择底部“合格才付款”。
2. 确认“交付情境”为“合格交付”。章节只是讲述顺序，实际运行内容以这个下拉框为准。
3. 点击一次“运行真实验收”。
4. 等待资金托管、签署承诺、生成证明、链上验证和结算完成。
5. 检查右侧显示“已付款”，金额为 0.002 测试 ETH；三行证据分别显示证明有效、验收合格、Provider 已收款。

成功后会出现实际订单号和结算交易哈希。每次重新运行都会创建新订单，不会覆盖上一笔。

## O04 运行过期交付并退款

1. 等当前运行结束，点击“不合格就退款”。
2. 确认情境为“过期交付”，点击“运行真实验收”。
3. 等右侧显示“已退款”，检查证明有效、验收不合格、买方已收回款项。

这里的过期是数据超过新鲜度要求，不是等待订单到期。当前样例的响应比订单参考时间早 600 秒，允许的最大年龄为 120 秒。

这笔退款使用了真实负面证明。不要把它讲成“证明失败所以退款”。

## O05 运行样本不足

在“交付情境”中选择“样本不足”，然后运行。预期是**证明有效、验收不合格、已退款**。

当前样例只有 24 条样本，订单要求至少 100 条。它用来说明同一套机制也支持字段阈值，不仅支持时间条件。

## O06 运行内容篡改

在情境下拉框中选择“篡改内容”，然后运行。预期显示“已拦截”，说明私密内容无法匹配 Provider 已签署的承诺，电路拒绝生成证明。

此时没有正常交付凭证，资金仍在托管。可继续执行 O08 的到期退款。

这是对**证明生成前的私密内容**动手脚；O13 则是修改**已导出凭证的公开结论**，两种操作验证不同环节。

## O07 运行伪造来源

选择“伪造来源”，然后运行。预期显示“已拦截”，原因是签名不属于订单指定的 Provider。

这条分支通过合约预执行观察签名拒绝，不会提交正常结算交易；资金仍在托管。继续用 O08 收回测试资金。

## O08 处理到期退款

当“篡改内容”“伪造来源”或中断运行留下待结算订单时：

1. 保留这笔运行在现场演示页，等待其他运行结束。
2. 点击“演示到期退款”。
3. 等待“到期已退款”，再展开“执行记录与交易证据”查看退款交易哈希。

按钮会推进**整条本地测试链**的时钟至该订单截止时间之后，再执行真实退款交易，所以无需现场等一小时。其他未完成订单的到期判断也会受到这次时钟推进影响。

到期退款没有形成交付证明，因此不会出现在普通交付凭证列表中，也不会增加 Provider 的不合格计数。

## O09 查看规则和执行证据

在现场演示下方展开：

- **查看验收规则**：查看数据年龄不超过 120 秒、样本量至少 100、置信度字段至少 90%，以及标的一致、价格大于零的要求。
- **执行记录与交易证据**：查看每个实际阶段的时间、证明大小、结算区块和交易哈希。成功结算后可点击“复制交易哈希”，或点击右侧交易条复制。

这里的交易属于本地链，不能直接到公共区块浏览器搜索。右侧“本次生成”是证明生成耗时，不是从点击到付款的总时间。

## O10 查看本机私密样本

运行过一个案例后，展开“本机私密样本”，点击“查看本机样本”。页面会显示该运行的合成标的、行情价格、样本量和置信度。再点击“隐藏样本”收起。

这适合开发调试；现场讲解隐私验收时可以一直保持关闭。公共凭证下载不包含这些原始字段。

服务重启后，旧运行的私密样本不再保留。如果页面提示该会话没有样本，重新运行一个案例即可。

## O11 导出凭证

完成付款或负面证明退款后，可以通过任一入口导出：

- 现场演示结果卡的下载图标。
- “公共凭证”中对应订单的下载图标。
- 核验页的“下载当前原始凭证”。

浏览器下载 `veilreceipt-订单号.json`。保存这个文件，稍后用于 O12 或 O19 的独立核验。

前两个入口下载本地结算记录；核验页下载当前选中或导入的原件。即使刚做过篡改副本实验，“下载当前原始凭证”仍下载原件。

## O12 导入并核验原始凭证

1. 点击结果卡的“带走并核验”，或选择底部“证据带得走”。
2. 点击“核验原始凭证”，检查显示“凭证有效”。
3. 要验证文件，点击“导入凭证 JSON”，选择 O11 导出的文件。导入后会自动发起核验。
4. 检查凭证格式、可信部署、来源签名、订单与规则、公开输入、零知识证明、结算事件和最终状态。

支持本项目的 JSON 凭证，文件大小上限为 100 KB。核验需要本地服务在线，以及文件对应的可信链和合约仍可访问。

来自另一套部署的文件可能被拒绝，即使它在那里曾经有效。要验证那套部署，请按 O19 显式指定相应的可信 RPC 与合约。

## O13 修改公开结果并再次核验

先核验一份有效原件，再点击“修改结果，再核验一次”。

预期显示“凭证被拒绝”。该操作只翻转副本中的验收布尔结果，原始证明、签名及交易保持不变；不会修改原始文件，也不会改变已经完成的链上结算。

点击“核验原始凭证”应重新通过。拒绝过程中可能提前遇到验证器异常，不要求所有后续检查项都列出；“本地服务未连接”则表示暂时没有核验结论，不能当作篡改被证实。

## O14 尝试重复结算

对已完成付款或退款的当前运行，展开“执行记录与交易证据”，点击“尝试重复结算”。

预期提示“重复结算已拒绝：这笔订单已经完成结算”。该按钮做合约预执行检查，不实际发送第二笔付款交易。

## O15 查看和筛选公共凭证

点击顶部“公共凭证”。可以按“全部结算”“合格付款”“不合格退款”筛选，查看订单号、金额、结算区块和交易哈希。

点击某条记录的“核验”会打开真实核验器并自动检查该记录；下载图标导出那条记录。顶部数字分别展示当前 Provider 的合格计数、不合格计数和仍托管的测试 ETH。

筛选只改变列表显示，不改变记录或链上状态。没有记录时，先运行 O03 或 O04。被拦截、尚未结算及无证明到期退款的订单不属于普通交付凭证。

## O16 查看部署和技术说明

点击顶部“技术说明”，查看三项机制、当前实现范围，以及当前本地部署的托管合约与验证器地址。

进行命令行复验时，可以从这里取得当前本机的托管合约地址。实际网络为 Local EVM，Chain ID 为 31337。页面中的 ERC-8004 链接用于阅读后续适配方向，不会执行链上操作。

## O18 断连和重启后恢复

页面显示“连接中断”时，先检查启动服务的终端。服务恢复后点击“重新连接”；页面也会周期性尝试刷新。不要把最后保留的结果误当作断连期间的新进度。

| 遇到的问题 | 处理方法 |
| --- | --- |
| 页面打不开 | 检查服务是否启动、端口是否为 4318；使用终端打印的地址 |
| 提示端口被占用 | 先确认原服务是否已经可用；不要对同一账本启动第二个进程 |
| 缺少电路或合约编译文件 | 首次安装完成 `npm run bootstrap`；缺少网页构建时执行 `npm run build` |
| 网络慢导致初始化失败 | 首次准备需要下载工具和参数；网络恢复后重试 bootstrap |
| 按钮灰色 | 检查连接状态以及是否仍有验收在执行；等当前运行结束 |
| 刷新后当前卡片没有旧订单 | 去“公共凭证”找到历史结算；重新导入之前保存的 JSON |
| 导入结果在刷新后消失 | 重新导入文件；上传的原件和当前核验结果没有持久保存 |
| 运行中服务停止 | 重启后若显示中断订单和到期退款入口，按 O08 处理；先查执行记录再重跑 |
| 旧 JSON 突然不能复验 | 检查是否切换或重新部署了链与合约；不要删除账本来修复核验问题 |

`.runtime` 保存演示账本、部署信息、公开运行记录和证明参数缓存。更新 UI 不需要删除它。旧账本丢失后，文件内的交易号本身不能恢复这条本地链。

## O19 使用 Agent 客户端和命令行核验

保持网站服务运行，在另一个终端进入项目根目录：

```sh
npm run agent -- valid
npm run agent -- stale
```

每条命令会创建一笔真实本地订单，等待结算，然后将凭证写到 `artifacts/agent-receipt-订单号.json`。记录输出中的实际文件名。

独立核验示例：

```sh
node scripts/verify-receipt.mjs artifacts/agent-receipt-1.json \
  http://127.0.0.1:4318/api/rpc YOUR_TRUSTED_ESCROW_ADDRESS
```

将示例文件名改成刚生成的文件，将 `YOUR_TRUSTED_ESCROW_ADDRESS` 替换为 O16 中当前可信部署的托管合约地址。命令必须从已完成 bootstrap 的项目根目录运行，读取本地编译的合约 ABI。

输出 `valid: true` 且八组检查通过表示通过；拒绝时返回非零退出状态。独立指核验程序可以在另一进程运行，它仍需要访问可信链数据，并不是完全离线核验。

## O20 演示前自检

按需要执行相应检查，不必每次演示都重新安装：

| 命令 | 前提与作用 |
| --- | --- |
| `npm test` | 已完成 bootstrap；使用独立新链检查证明、资金和对抗用例，不修改演示账本 |
| `npm run test:model` | 检查界面的证明、验收、结算状态映射 |
| `npm run test:stage` | 默认 4318 服务已启动，且至少有一份凭证；复验原件和篡改副本 |
| `npm run test:rehearsal` | 默认 4318 服务已启动且空闲；连续三轮各做一次付款与退款，并检查复验、篡改、重放；会新增六笔演示订单 |
| `VEIL_TEST_URL=http://127.0.0.1:4318 node --test tests/http.test.mjs` | 服务已启动；检查接口输入、Host / Origin 与只读 RPC 防护，不新建订单 |

现场前确认：付款和退款都跑通；原件通过而副本拒绝；JSON 已保存；演示窗口字号可读；讲稿顺序已经熟悉。历史测试结果见 [发布审阅](REVIEW.zh-CN.md)。

正式对外使用前的安全范围和依赖情况见 [安全说明](../SECURITY.md)。
